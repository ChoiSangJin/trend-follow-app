# 말문 — 오늘의 스몰토크

한국어 뉴스에서 확인할 수 있는 소식을 편집한 배경 설명·대화 흐름·내 기록으로 연결하는 Android 앱입니다. 홈은 기사를 많이 읽는 대신 최대 3개의 주제를 대화할 만큼 이해하는 흐름입니다.
이전 Follow MZ와 별개 앱이며 패키지 ID는 `com.malmun.app`, 버전은 3.0.0입니다.

## 사용자 경험

- 오늘의 말문: 준비된 배경 설명과 두 출처 이상의 인용이 있는 최대 3개 브리핑, 서로 다른 분야·아직 익히지 않은 개념 우선
- 대화 상대: 회사 동료 / 친구 / 처음 만난 사람에 맞춘 첫마디와 후속 질문 2개
- 이해와 적용: 선택형 생각해 보기, 이해 표시, 내 말로 한 문장, 새로 알았어요·이미 알아요·대화에 써봤어요
- 내가 이해한 이야기: 이해·사용 기록과 메모를 기기에 저장하고 재실행 후 복습
- 분야별 소식 둘러보기: 기존 7개 분야별 최대 2개·총 14개 목록과 필터 유지
- 최근 3일 화제: 별도 탭에서 한국어 보도의 출처 범위로 최대 30개 순위, 분야 필터, 24시간 구간별 출처 수 그래프, 보도 증가 필터
- 대화 준비: 기사 제목, 출처 그룹 수와 보도 지속 기간, 선정 근거 링크, 질문 복사, 대화 시 참고점, 원문 링크 및 발행 시각
- 보관함: 소재와 질문을 로컬에 저장하여 재실행 후에도 열람
- 오프라인: 마지막 성공 브리핑을 저장. 최초 접속 실패 시에는 ‘대화 연습 모드’를 명시한 기본 질문 제공
- 시스템 라이트/다크 테마, 큰 글꼴, 모바일 화면에서 가변 높이 카드
- 청록색과 크림색 말풍선 아이콘, 코랄색 보조 말풍선

## 정보의 범위와 정확성

Google 뉴스 한국판의 분야별 주요 기사 RSS와 주제 검색 RSS를 사용합니다. 주요 기사 피드를 우선하고 후보가 부족하면 키워드 검색과 사건별 추가 검색을 사용합니다. 문화·예술은 미술관·공연·신간을, 스포츠는 야구·축구·농구·배구·골프·테니스를 나누어 찾습니다. 논리적 요청은 문화 최대 5회, 스포츠 최대 6회, 나머지 분야 최대 3회이며 일시 오류 재시도는 요청당 한 번입니다. 한국어 언어 코드와 한국판 `ceid=KR:ko`를 확인하고,
발행 후 6~72시간인 기사만 선택하고 출처의 publisher URL을 명시한 언론사 도메인 목록과 대조합니다. 분야 적합성을 필터링하고 같은 사건의 기사를 묶습니다. 같은 매체, 확인 가능한 통신사 전재 및 매우 유사한 제목은 출처 그룹 하나로 계산합니다. 2개 이상 출처 그룹이 확인된 주제를 우선합니다. 전재 탐지가 완전하지는 않습니다. 문화·예술과 스포츠의 부족한 자리에는 날짜와 출처가 있는 단일 출처 기사를 추가 읽을거리로 제공하며 카드와 상세에 **단일 출처 · 인기 확인 전**을 표시합니다. 이 기사 수나 전재 횟수를 대중 인기의 근거로 사용하지 않습니다. 그룹 수, 보도 지속 기간, 마지막 보도 시각 순으로 각 분야에서 최대 2개를 선정합니다.

이는 최근 3일의 보도 확산을 나타내는 대리지표입니다. 검색량·조회수·공유 수 기반의 대중 인기 순위나 조작 방지를 보장하지 않습니다. 단일 매체의 기사 수만으로 순위를 높이지 않습니다. 후보가 부족하면 확인되지 않은 사건을 추가 검색하며, 실제 기사가 전혀 없으면 빈 분야로 표시합니다. 경제·주식은 금리·물가·증시·기업 소식, 세계뉴스는 국제 외교·무역·기후·보건 등 한국어 보도를 다룹니다. 시세는 실시간이 아니며 투자 판단 자료로 제공하지 않습니다.
문화·예술은 전시·공연·책, 연예는 공개된 신작·활동, 사회는 제도·교통·교육 등 일상에 연결되는 소식 위주로 선별합니다. 자동차 등 산업 전시를 문화·예술로 넣지 않고, 연예는 작품·활동 제목이 확인되는 기사로 좁힙니다. 기술·과학에서 투자·펀드 기사를, 사회에서 의회 일정·해외 행사 홍보를 제외합니다.
필터는 완전한 안전성이나 편집 품질을 보장하지 않으므로 원문을 확인하세요.

**인기 순위, 인스타·틱톡의 실시간 밈 순위, 기사 본문을 읽은 AI 요약을 제공하지 않습니다.**
기사 제목만 확인 가능한 현재 수집 방식에서는 제목을 그대로 전달하고 ‘제목 기반 정보’임을 표시합니다.
질문과 참고점은 분야별 편집 템플릿이며 취재된 사실로 제시하지 않습니다.
정확한 본문 요약이 필요하면 이용 허가된 원문 소스 또는 별도 편집 검수를 추가해야 합니다.

6시간마다 Actions가 피드를 갱신합니다. 적합한 기사가 부족하면 14개 미만이 될 수 있으며
전부 실패하면 마지막 정상 피드를 보존합니다. 일부 분야만 새 수집에서 빠지면 이전 확인 기사의 모든 근거 보도가 현재 기준 6~72시간 범위인 경우만 유지하고, 상세에 이전 수집 시각을 표시합니다. 오래된 피드는 앱에서 이전 브리핑으로 표시합니다.
실제 기사 발행 시각과 수집 시각을 구분하며 KST로 표시합니다.
API 비밀키나 유료 모델 없이 작동합니다. 공개 피드의 가용성에 따라 수집이 실패할 수 있습니다.

## 개발 및 테스트

Flutter 3.47.9 stable, JDK 17, Android SDK 36, Flutter 지정 NDK.
기존 체크아웃을 사용하세요. 클라우드 작업은 격리되어 있어 별도 worktree는 필요하지 않습니다.

```sh
flutter pub get --enforce-lockfile
flutter analyze --fatal-infos
flutter test --reporter expanded
python3 -m unittest discover -s scripts -p 'test_*.py' -v
python3 scripts/collect_briefing.py
bash scripts/prepare_test_key.sh
flutter build apk --debug --target-platform=android-arm64
```

Android 7.0(API 24)+ ARM64용입니다. `BRIEFING_ENDPOINT` dart-define으로 HTTPS JSON 주소를 교체할 수 있습니다.
기본 주소는 이 저장소 main의 `data/briefing-v5.json`입니다. 오프라인 연습은 `assets/practice.json`이며
실제 기사로 표시하지 않습니다. 커밋된 pubspec.lock으로 전이 의존성을 고정하며 CI metadata artifact에서도 확인할 수 있습니다.

기존 화면의 PageStorage에 펼침 상태(bool)와 스크롤 위치(double)가 같은 키로 저장될 수 있는
구조를 제거했습니다. 펼침 위젯 대신 독립 상세 화면을 사용하고 목록별 스크롤 키를 분리했습니다.
화면 전환·보관·필터·상세 뒤로 가기·큰 글꼴 회귀 테스트로 검증합니다.

## 배포

`Publish tested APK`를 수동 실행하여 성공한 **main CI**의 run_id와 태그를 지정합니다.
테스트한 소스와 태그 일치, APK 서명, 기존 말문 v2.0.0과의 서명 일치, arm64-v8a ABI를 검증한 뒤 Release에 APK·SHA256SUMS를 첨부합니다.
`Malmun-arm64.apk`는 개발용 서명 배포본입니다. 기존 Follow MZ와 패키지 ID가 달라 동시에 설치 가능합니다.

main CI는 `android/.test-signing/debug.keystore`를 고정된 Actions cache key로 재사용합니다.
Gradle debug 서명도 이 파일을 직접 가리키며 CI에서 파일이 없으면 빌드를 중단합니다.
표준 Android debug 비밀번호를 사용하는 테스트용 키이며, 키 파일은 Git이나 Release에 넣지 않습니다. 캐시가 유지되는 동안 후속 업데이트의
서명이 유지됩니다. 캐시 만료/삭제 후에는 서명이 바뀔 수 있으므로 영구적인 배포 키 보관을 대체하지 않습니다.
최초 배포는 main CI의 빌드를 사용해 main 캐시에 키를 남깁니다.

별도 영구 배포 키를 사용할 경우 `ANDROID_KEYSTORE_BASE64`, `ANDROID_STORE_PASSWORD`,
`ANDROID_KEY_PASSWORD`, `ANDROID_KEY_ALIAS` repository secrets가 필요하며,
`Release ARM64 APK`를 버전 태그 ref에서 수동 실행합니다. secrets 값은 Git에 넣지 마세요.
이 배포 경로는 기본 테스트 배포에 필요하지 않습니다.

구버전 앱을 위해 `data/briefing.json`에는 schema_version 2와 최대 5개를 유지합니다.
v2.1 앱용 `data/briefing-v3.json`에는 schema_version 3과 기존 5개 분야·최대 10개를 유지합니다.
v2.2용 `data/briefing-v4.json`(schema 4)은 출처 그룹 2곳 이상만 유지합니다. v2.3 앱은 `data/briefing-v5.json`의 schema_version 5에서 7개 분야·분야별 2개·총 14개 제한과 출처 근거의 수·시각·기본 기사 일치를 검사합니다. 기존 보관함은 유지하고 이전 분야 이름도 보관함 필터에서 그대로 열 수 있습니다.

## 최근 3일 화제 탭

`data/trends-v1.json`은 기존 분야별 대화 추천과 독립된 피드입니다. 한국판/한국어의 최근 0~72시간 기사를 대상으로 하며, 대화 추천의 6~72시간 규칙은 유지합니다. 단일 출처 기사는 화제 순위에 포함하지 않습니다. 여러 매체의 관심을 나타내는 보도 표본이며 한국 전체의 조회수나 검색량·SNS 인기 순위가 아닙니다.

`data/trends-history.json`에 기사 ID·출처·발행 시각과 수집 성공 분야 이력을 72시간 보관하고, 분야별 최근 기사 최대 600개·관측 최대 1000회로 제한합니다. 같은 URL, 매체, 확인 가능한 통신사 전재, 유사 제목을 중복 계산하지 않습니다. 주요 화제는 전체 관측 출처 그룹 수·지속 시간 순이며 원문 근거 링크는 최대 8곳입니다. 그래프는 오래된 구간부터 48~72시간 전/24~48시간 전/최근 24시간의 보도 출처 그룹 수입니다. 같은 출처는 각 구간에서 한 번만 계산합니다.

분야별로 고정된 주요 기사/키워드/세부 분야 검색만 화제 이력에 반영하며, 추천용 사건별 추가 검색은 제외합니다. 6시간마다 저장한 연속 48시간 이상의 이력이 쌓이고, 이전 24시간 출처 2그룹 이상·최근 24시간 3그룹 이상·50% 이상 증가한 주제만 ‘보도 증가’로 표시합니다. 8시간 넘는 공백, 이번 분야의 고정 수집 일부라도 실패, 표본 상한 도달 시 비교를 보류합니다. 이전 구간이 0이면 무한 증가율 대신 ‘새로 포착’입니다. 첫 배포에서는 주요 화제를 바로 볼 수 있으며 증가 비교는 ‘집계 중’입니다. 잦은 수동 실행으로 시간을 채우지 않습니다. 제한된 RSS 표본과 제목 자동 묶음의 한계가 있으므로 완전한 인기 순위나 조작 방지를 보장하지 않습니다.

화제 탭은 별도 캐시와 새로고침·재시도를 사용합니다. 오프라인은 이전 집계임을 표시하고 수집 시각을 보여주며, 최초 접속 실패 시 가짜 순위나 연습용 뉴스를 만들지 않습니다. `TRENDS_ENDPOINT`로 HTTPS 피드 주소를 변경할 수 있습니다.

## 이해하고 대화하는 브리핑 (3.0)

`assets/conversation_guides.json`에는 전시·공연 통계·독서·축구 기여·연승·주가지수·업무 AI·교통·음악·국제회의 등 10개의 편집 배경 설명과 이해 확인·상대별 대화 흐름이 들어 있습니다. 현재 뉴스 제목의 범주와 구체적인 소재가 맞는 경우에만 연결합니다. 배경과 대화 접점은 앱이 편집한 일반 개념 설명이며 기사 본문 요약이나 새로 취재한 사실로 표시하지 않습니다. 공식 사이트 링크는 추가 자료 탐색용이며, 특정 기사 사실의 근거는 각 언론사의 날짜·원문 링크와 실제 기사 제목 인용으로 구분합니다.

수집 피드의 `coverage.sources[].headline`에는 해당 출처의 실제 제목을 보존합니다. 기존 클라이언트는 추가 필드를 무시하며 새 클라이언트도 이 필드가 없는 예전 보관 자료를 계속 읽습니다. 오늘의 카드에는 최근 6~72시간이고 두 출처 이상 실제 제목이 남아 있으며 준비된 편집 가이드와 맞는 기사만 올립니다. 충분하지 않으면 3개를 임의로 채우지 않습니다. 보관함과 화제 탭에서도 맞는 가이드가 있으면 같은 브리핑으로 이어집니다.

`conversation-learning-v1`에는 대화 상대, 이해 표시·피드백, 기사와 가이드 ID, 사용자 메모를 최대 150개 기기 내에 보관합니다. 북마크 키를 변경하지 않으며 기록을 서버로 전송하지 않습니다. 저장은 순서대로 처리하고 실패 시 이전 상태를 유지합니다. 한국 날짜가 바뀌거나 상대를 바꿀 때 새로 고르고, 이미 읽은 주제·개념보다 새로운 것을 우선합니다. 한 세션에서 이해 표시만으로 카드 순서가 바뀌지는 않습니다.
